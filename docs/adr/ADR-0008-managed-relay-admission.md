# ADR-0008：托管租户的公共中继配置与准入

- 状态：Accepted
- 日期：2026-10-09

## 背景

托管组织的创建工厂此前只装配状态目录、服务器地址、时区和反代设置，没有
DERP map。自助注册得到的新网络因此没有部署提供的中继。多租户按 Host 路由
后，中继向回环地址请求 `/derp/admit` 也无法匹配租户。

上游 `tailcfg.DERPAdmitClientRequest` 只有节点公钥和来源地址，没有租户字段。
不能为平台准入增加不兼容的客户端参数，不能把某个组织的私有配置自动复制给
其它租户。

## 决策

- 多租户增加显式部署选项 `-managed-derp-map <file>`。该文件是公共中继池，
  为新建及重启恢复的托管组织装配 DERP map，保留其中的端口、证书指纹和 STUN
  配置。已配置的组织继续使用各自的 `derp_map`。
- 配置公共池时，Router 挂载 `POST /api/relay/v1/admit`，接受并返回上游
  `DERPAdmitClientRequest` / `DERPAdmitClientResponse`。中继仍使用官方
  `--verify-client-url` 协议，已有租户端点 `/derp/admit` 保留。
- 公共池准入在各租户内按节点公钥查找，要求节点已注册、未过期，且该租户
  的有效 DERP map 包含与公共池一致的中继节点。随后执行该租户的 DERP 策略。
  未知公钥、已过期节点、禁用中继及只配置私有中继的租户均拒绝。
- 公共池只提供中继传输。客户端仍从自己的控制面获得对等节点和访问策略；
  准入不会合并 tailnet、授予会话或修改设备身份。
- 自助入口的旧 `/api/v1/auth/signup` 和 HTML `/signup` 不再创建入口租户成员。
  注册者使用平台自助端点创建独立租户，避免绕过控制台造成公共网络混用。

## 影响

- 协议兼容：使用既有上游消息类型，TS2021、Noise、注册与 Map 语义不变。
- 安全：公共池显式启用，逐租户验证有效配置与策略，错误请求拒绝；不继承
  入口租户的密钥、OIDC、ACL 或用户数据。
- 数据：无数据库迁移，重启从持久组织记录恢复相同装配。
- 运维：中继的 verify URL 改为回环地址的 `/api/relay/v1/admit`，公共池配置
  必须同时部署到控制面；单租户部署继续使用 `/derp/admit`。

## 验证

配置工厂与重启恢复测试、注册入口旁路拒绝、逐租户准入矩阵，以及官方上游
Noise 客户端注册和 Map 集成测试验证分配地址、公共中继和对等节点隔离。
