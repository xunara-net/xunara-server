# ADR-0018：持久网络配置与统一可视化策略

- 状态：Accepted
- 日期：2026-10-10
- 决策者：Xunara 维护者（按用户要求推进）
- 提案：[网络控制台](../proposals/2026-10-10-network-console.md)

## 决策

平台新增 `networkconfig`，Core 不依赖页面模型。可视化和 HuJSON 共用
`policy.Document` 与现有 Compiler，不建立第二套权限解释器。发布/恢复要求
CAS，并在同一 SQLite 事务中复核会话/角色、记录版本/审计、撤销 SSH check、
推进配置通知。state 追加 v20 表结构，不修改历史迁移。

未托管时保留文件与启动配置；发布后数据库独占权威，文件不能反向覆盖。
完整坏配置失败关闭；运行读取故障保留有效快照而非放开网络。首次发布保存原始
配置版本 0，历史恢复始终生成新版本，不用删除配置恢复默认互通。

DNS 页面仅编辑官方客户端支持的地址记录和 DNS 设置；机器与 ACME 记录受保护，
域名仍由部署管理。菜单移动为手机侧边抽屉，DNS、访问权限、中继独立功能页。

## 备选方案

- 直接改运行 maps：并发不安全、重启丢失、无法审计，拒绝。
- Web 覆盖 ACL 文件：文件和审计非原子、跨实例/版本竞争，拒绝。
- 单独可视化权限引擎：与实际客户端 PacketFilter 漂移，拒绝。

## 影响与后续

不改变官方 wire 协议、身份键或既有设备地址。新增管理 API 和 v20 迁移。
人类写入要求 owner/admin 与 CSRF；自动化要求 write Scope 和 API Entitlement，
事务内重新验证持久凭据与所有者角色，不混淆 Human / Service 身份。
保留旧配置无策略时完全互通的兼容语义，必须在 UI 明示，不声称是默认隔离。
生产 HTTPS、全 OS 实测、完整计费和中继自动升级不由本 ADR 宣称完成。
