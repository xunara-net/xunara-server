# ADR-0011：通行密钥迁移到独立 Web 与账户认证收敛

- 状态：Accepted
- 日期：2026-10-09

## Architecture Change Proposal

服务端已有持久化 WebAuthn 验证器，但通行密钥管理仍在内嵌控制台，独立 Web
没有登录入口。旧会话 API 和退出接口也各自执行撤销与审计，存在存储失败后仍
报告退出成功的路径。本次按功能切片迁移，不为清理旧 UI 删除官方客户端所需
的浏览器授权页面，也不一次性删除尚未完成 Web 功能对等的其他控制台模块。

## 决策

- 通行密钥登录与账户管理接入独立 Web，所有入口复用既有 PasskeyService、
  WebAuthn 库验证、持久化单次挑战和浏览器绑定。人类登录不会自动批准设备。
  RP ID、Origin allowlist、用户验证和 HTTPS 要求不放宽。
- 新增账户范围通行密钥 JSON API，仅接受本租户有效 Human Session；写操作
  必须校验当前会话的 CSRF 头。列表只返回名称、公共标识、创建和使用时间，
  不返回 credential ID、公钥、挑战状态或 Cookie 绑定秘密。
- 登录签发会话时在事务中再次确认凭据和所属用户仍存在，避免验证期间已删除
  的凭据继续签发新登录；会话创建和成功审计同事务提交。
- 注册提交和删除在事务内再次检查发起 Session，凭据变更与成功审计一起提交；
  删除仅匹配当前用户，未知或他人目标统一返回不存在。列表读取错误不得伪装
  成空列表。挑战在验证前原子消费，失败后需重新发起，不恢复挑战供重放。
- 删除服务端旧通行密钥管理模板、脚本和业务处理器；旧页面只重定向到独立 Web
  安全中心。旧管理地址暂时保留带 Deprecation 头与迁移文档链接的薄适配，复用
  新账户接口的权限、事务和审计，不维护第二套实现，最终删除另行公告。
  旧公共通行密钥登录路由保留同一处理器，供官方客户端必需的 HTML 登录使用。
- 旧会话列表保留字段兼容的薄适配，删除旧撤销实现并转用账户撤销事务。
  旧写接口收紧为 Human Session + CSRF；服务 API Key 不能管理人类登录。
  JSON 退出继续支持匿名重复调用，但有效登录的退出必须有 CSRF，持久撤销失败
  时不清 Cookie、不报告成功。HTML 退出同样使用事务撤销并校验表单 CSRF。
- Web 删除不再使用的旧会话接口、类型和转换器；顶部退出和安全中心调用同一
  账户撤销接口。网络或服务器失败时保留 UI 登录态，展示错误并允许重试。
- 在相关源码补充中文注释，重点解释身份边界、重放防护、事务一致性与兼容
  适配的保留原因，避免逐行翻译或保留大段注释掉的旧实现。

## 影响

- 无数据库结构变更，已发布迁移不修改；使用已有凭据、会话、挑战和审计表。
- 增量 JSON API；旧会话写 API 的服务身份访问和无 CSRF 写入不再支持。
  旧通行密钥管理地址先弃用并迁移到安全中心；其他未迁移控制台功能暂时保留。
- 不修改 TS2021、Noise、Register、Map、DNS、DERP、套餐或设备信任语义。
- 当前公网 HTTP 调试部署不能使用浏览器通行密钥；界面解释原因，不将其伪装
  为可用。安全部署需固定域名、HTTPS 和匹配该租户的 WebAuthn 配置。
- 本次不是 TOTP/2FA、账号找回、完整登录历史或密码重认证项目；通行密钥与
  原登录方式可以并存，删除前由界面提示保留其他可用登录方式。

## 参考及验证计划

已检查 go-webauthn 上游注册/登录验证及序列化字段，使用库完成 challenge、
RP ID、Origin、用户句柄、签名及用户验证，不自建 WebAuthn 验证器。
浏览器二进制字段按 [WebAuthn Level 2](https://www.w3.org/TR/webauthn-2/) 转换；
接口弃用使用 [RFC 9745](https://www.rfc-editor.org/rfc/rfc9745.html) 的日期头与
`deprecation` 文档链接，遵守补充规格 §110 的渐进迁移要求。

验证 JSON 契约、成员权限、服务身份拒绝、CSRF、跨用户/租户隔离、挑战重放、
浏览器绑定、事务回滚和撤销后的注册/删除拒绝；完整 Go build/vet/test/race，
前端类型检查与测试，真实浏览器虚拟认证器完成注册、登录、删除和失败重试。
