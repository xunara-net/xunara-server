# ADR-0040：独立平台身份与多通行密钥

- 状态：Accepted
- 日期：2026-10-13
- 背景：[Proposal](../proposals/platform-passkey-administration.md)

## 决策

部署运营者的人类身份使用独立持久数据库，绝不借用租户 owner 或邮箱匹配。
恢复令牌仅负责引导登录；成功后签发四小时平台 Bearer 会话，不把永久令牌交给
Passkey 登录者。沿用 go-webauthn 与已有持久挑战验证，固定管理员 origin，要求 UV。

允许同一运营者绑定多把通行密钥；注册复查发起会话，解绑与全部 Passkey 会话
撤销同事务，缺少恢复方式时保护最后一把。凭据写入要求最近十五分钟验证。
既有平台令牌自动化保持不变；不使平台会话成为租户、机器或服务身份。

平台创建本地成员是独立授权入口，明确选定已有网络并使用当前成员 Entitlement；
账户、凭据、本地身份、额度检查及必需审计同事务，不依赖公开注册或邀请码，
不附带用户会话、设备审批或新的 Tailnet。

## 影响与限制

不改变 TS2021/Noise 等官方协议和已发布迁移。新文件必须纳入备份，升级可以
关闭平台 Passkey 或回退旧二进制，保留文件供未来重新启用。
本决策不交付多运营者 RBAC/TOTP/完整恢复；跨数据库授权与套餐变更不声称原子，
现有跨租户审计尚不包含独立平台凭据日志。虚拟认证器不代表所有真实平台已验收。

## 实施补充：认证器身份域（2026-10-13）

平台使用稳定 WebAuthn handle 身份域，避免同 RP 下与租户数字 ID 重合导致
认证器替换旧驻留凭据；不改变已发布租户 handle。依据
[WebAuthn user handle](https://www.w3.org/TR/webauthn-3/#user-handle) 的 RP/handle 对映射。
