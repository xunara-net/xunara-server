# ADR-0010：用户自助会话管理与事务型批量退出

- 状态：Accepted
- 日期：2026-10-09
- 决策者：Xunara 开发者

## 背景

规格 §11–§12 要求退出当前、其他和全部控制台登录。现有逐个撤销接口没有
批量操作；会话列表混合活动、过期和已撤销记录，存储读取失败也可能被当成空列表。
自助安全操作必须与管理员强制下线、机器身份和服务身份分开。

## 决策

- 新增账户范围的会话列表、单个撤销和批量撤销接口，复用持久化 Session 表。
  只有 Human Session 可以调用；所有写请求必须携带与当前会话绑定的 CSRF 头。
  普通成员也可以管理自己的登录，不受网络写权限或套餐 API 权限限制。
- 列表返回服务端判定的活动、过期或已撤销状态，以及当前会话标识和 CSRF 令牌。
  读取失败明确报错，不把存储错误转换为空列表。不返回会话令牌或其哈希。
- 撤销事务内再次确认发起会话属于当前用户、未过期、未撤销且用户仍存在；
  单个目标也必须属于同一用户。租户由既有 Host 路由和独立 Identity Store 隔离。
  未知或其他用户的目标统一返回不存在。
- 支持单个、其他、全部三种明确选择。只更新事务执行时仍活动的会话，
  “其他”严格保留发起会话。撤销计数与成功审计同事务提交；任一写入失败全部回滚。
  重复撤销已失效的单个目标或重复退出其他登录返回零次变更，不重写历史原因。
- 轮换继续使用已发布的活动会话条件更新；轮换先提交的替代会话会被批量操作覆盖，
  撤销先提交则旧会话不能被轮换复活。发起会话在事务前失效时拒绝整个操作。
- 批量退出只撤销事务执行时的登录，不改变密码、不撤销身份提供方登录、
  不阻止之后用有效凭据重新登录。怀疑密码泄露时还须修改密码。
  不影响机器连接、预认证密钥、API Key 或其他用户/租户。
- UI 分开显示活动登录与保留的失效会话记录，提供确认、忙碌与失败状态；
  不伪造尚未采集的浏览器型号、来源 IP、城市或最后活动时间。
  安全概览改为中文状态与提示，不把原始 JSON 当作最终用户界面。

## 参考与备选

已检查 Dex 上游 `server/tokens/refresh_store.go` 的定向/全部撤销与
`refresh_store_test.go` 的边界测试，参考其明确区分撤销范围的原则，不复制
OAuth refresh-token 实现。逐个 HTTP 请求拼成批量操作无法保证原子性；
本地 map 不能跨实例或重启持久化，因此均不采用。

## 影响

- 不修改数据库结构或已发布迁移，不修改官方 Tailscale 协议与客户端行为。
- 新增账户 API；既有 Session API 和平台管理员撤销接口保留兼容。
- 审计只包含公共会话标识、操作范围和计数，不含 Secret。
- 当前列表是仍保留的会话记录，不是完整登录历史；清理任务可能移除过期记录。

## 后续

独立设计登录审计、可信代理下的来源元数据、2FA 与邮箱验证；
当前 HTTP 调试环境仍不等同于具备 HTTPS 的正式安全部署。
