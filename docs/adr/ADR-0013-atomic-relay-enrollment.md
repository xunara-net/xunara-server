# ADR-0013：中继注册的原子配额与凭据交换

- 状态：Accepted
- 日期：2026-10-09
- 补充：ADR-0006，不改变其管理面/数据面及租户归属决策。
- 提案：[中继注册事务边界](../proposals/2026-10-09-atomic-relay-enrollment.md)。

## 决策

产品注册只使用 `RelayStore.EnrollRelay`：一次性凭据验证、当前中继数量检查、
长期身份插入及凭据消费在同一写事务内完成。请求内容校验和随机值生成必须在
提交前完成；失败不留下已消费令牌或孤立身份。事务内再次验证令牌，防止之前
读取与实际提交之间的撤销、过期或重放竞争。

套餐额度由控制面 Entitlement 提供，存储层仅接受数值，不引用套餐名称。
SQLite 沿用现有即时写事务，独立连接竞争同一数据库时也不能超额；内存实现
在同一锁内遵守相同契约。删除只消费令牌的旧写接口，避免新旧提交方式混用。

认证读取增加 context 和显式错误返回。未知令牌仍是 401；存储故障返回不含
内部细节的 503，不伪装成无效身份；配额、重放与过期沿用已有错误码。

## 影响与边界

- 不修改数据库结构、既有迁移、产品成功响应或任何官方客户端协议。
- 配额拒绝及持久化故障后，同一个未过期令牌可在资源或存储恢复后重新注册。
- 独立模式、心跳、准入和 DERP 转发不变。底层 `CreateRelay` 不是产品注册入口。
- 注册后的审计仍沿用既有路径，未与注册事务绑定；不能据此宣称审计写入故障
  也会回滚注册。提交后 HTTP 响应丢失的恢复、多实例套餐变更与注册竞争、心跳
  的历史布尔查询，以及其他资源的配额原子性仍须专项补齐。

## 验证

共享契约覆盖内存/SQLite 的额度、取消、重复节点与凭据、失败后重试、过期及
重放。SQLite 触发器在身份插入后拒绝令牌更新，验证两者一起回滚；两个独立
连接并发竞争验证额度与单次消费。真实 HTTP 测试覆盖跨租户、故障分类、错误
脱敏、禁止缓存与恢复。完整测试结果统一记录在文档中心的实现与审查台账。
