# ADR-0014：正式 Web 认证入口与原子成员邀请

- 状态：Accepted
- 日期：2026-10-09
- 补充：ADR-0003、ADR-0007、ADR-0012；不改变身份、租户或协议归属。
- 提案：[认证入口与邀请事务](../proposals/2026-10-09-browser-auth-and-member-invitations.md)。
- 跨仓库追踪：[server #1](https://github.com/xunara-net/xunara-server/issues/1)。

## 决策

提供方通过同源 API 路径启动浏览器认证，复用既有持久 AuthTransaction、固定回调、
state/nonce/PKCE/JWKS 验证和浏览器绑定。不让代理按查询参数区分 SPA 与后端页面。
正式 Web 保留产品页面及后端设备授权目标；站外、反斜杠等异常回跳拒绝。
新旧第三方入口共享持久 IP 限流，存储故障拒绝开始；不记录提供方原始错误正文。

本地成员注册只有一个提交入口，事务内校验当前成员额度、邀请未使用且未过期，
写入账户、凭据、`(local, login)` 链接、兑换记录、会话及审计。角色只能来自事务内
读取的邀请；无邀请开放注册只授予 member。密码哈希在事务前计算，失败全量回滚，
不再先创建后补偿删除，也不保留独立兑换写接口。

正式邀请 API 只接受 owner 人类会话；写入必须校验 CSRF，并在事务内再次检查会话
和角色，创建/撤销与审计共同提交。旧表单复用同一业务实现，收回 admin 发邀请权限。
新邀请必须有有效期，只能授予已有 member/admin，不能授予 owner；不为 UI 增加
未实现的 viewer/network-admin 角色。邀请不预占名额，兑换再检查实际使用量。

邀请码只在创建响应和当前弹窗展示，关闭/离开页面清除；不进入 URL、日志、审计或
浏览器持久存储。分享注册页面地址和代码是两个独立动作。既有旧邀请仍可兑换；
旧带代码书签只保留接收兼容，不继续生成。

## 影响与未覆盖边界

- 不修改数据库结构、已发布迁移、套餐额度值或官方客户端 wire 协议。
- HTTP 成功意味着整个本地注册提交完成；会话或审计失败不留下半注册账户。
- SQLite 沿用即时写事务，多个连接争夺最后名额不能一起成功。
- 第三方首次建号、管理员其他建号路径、角色变更及跨库套餐修改的并发原子性
  仍需继续审查。本决策不声称全部成员创建路径都已经原子化。
- 当前支持三种服务端角色。Viewer/Network Admin、邮箱验证/找回、2FA、邀请通知、
  响应丢失的幂等恢复及多实例部署验收未完成。
- 本地 OIDC 夹具证明正式同源路由、签名、nonce、PKCE、浏览器绑定和回跳链路，
  不等同于已配置公网 Google/GitHub、生产 HTTPS 或实际设备审批成功。

## 验证与发布门槛

本地注册逐表故障回滚、跨连接最后名额与邀请写事务的定向竞态验证通过；真实
Chromium 23 阶段通过，Web 92 项、超管 25 项测试及类型/构建检查通过。
首轮完整 race 发现新限流故障夹具在启动后台观察器后替换 Store 指针；现改为
隔离 SQLite 触发器注入故障，不为测试修改生产同步或跳过断言。
完整 build/vet/test/race 与 CI 必须通过后才能部署；最终结果以文档中心验收记录
为准，本设计接受不等于所有规格功能完工。
