# ADR-0009：账户自助资料与密码变更

- 状态：Accepted
- 日期：2026-10-09

## Architecture Change Proposal

用户中心目前只能查看账户资料，密码只能由初始化或注册流程写入。直接复用
租户用户管理接口既不能满足普通成员的自助需求，也会将人类账户操作混入服务
身份的权限。新增独立的账户接口，保持现有登录、设备授权和官方客户端协议不变。

参考本地 Dex 上游的事务型密码更新及并发一致性测试；不采用其邮箱主键。
账户仍以本租户的用户 ID 定位，外部身份仍以 `(provider_id, subject)` 定位。

## 决策

- `GET/PATCH /api/v1/account` 和 `POST /api/v1/account/password` 只接受本租户
  有效的人类 Session，拒绝 API Key。普通成员可以更新自己的昵称及联系邮箱，
  不能提交用户 ID、登录名、角色、组织或外部身份。
- 写请求必须携带由 Session 派生的 `X-CSRF-Token`，由账户读取接口提供；严格
  解码限长 JSON，不在错误、审计或日志中输出密码和密码哈希。
- 邮箱仅是未验证的联系属性；本次不实现邮箱验证、找回密码、身份合并或 2FA。
- 修改密码必须验证当前密码，沿用注册时的长度及 UTF-8 策略，拒绝未变更的
  密码。无本地密码或禁用本地登录的账户不能在此创建或更改密码。尝试次数走
  持久限流，存储故障时拒绝操作。
- 密码更新使用期望旧哈希的 compare-and-swap，并确认发起会话仍有效。在同一
  数据库事务中替换哈希、撤销该用户全部会话并写入审计。失败全部回滚；成功
  清除当前浏览器 Cookie，要求所有浏览器重新登录。
- 自助注册的父域 Cookie 与后续登录的主机 Cookie 可能同名并存；读取时逐一
  检查本租户的持久 Session，忽略已撤销或属于其他租户的 Cookie，避免改密后
  残留的父域 Cookie 遮蔽新登录。
- 密码登录创建 Session 时，在事务内确认已验证的哈希仍然有效，避免旧密码
  登录与密码修改并发时签发新会话。Session 轮换也必须在事务内确认原会话未
  撤销且未过期，不能通过轮换恢复密码修改前的会话。
- 资料更新只写昵称、联系邮箱和更新时间，避免并发角色调整被旧 User 快照覆盖。
  资料更新及审计同事务。原租户用户管理写接口只允许 owner，普通成员使用自助
  账户接口，admin 不可修改其他用户。

## 备选方案

- 用 `PATCH /users/{id}` 兼做自助：拒绝，角色与服务密钥的边界不同。
- 先写密码再单独撤销 Session：拒绝，存储失败或并发登录可能保留旧会话。
- 使用进程内锁解决并发：拒绝，不能覆盖多实例，也不保证崩溃后的数据完整性。

## 影响

- 兼容性：增量账户 API；原用户管理权限收紧到既有 owner 角色语义。TS2021、
  Noise、Register、Map、DERP 和设备信任不变，既有机器及服务密钥不因改密撤销。
- 数据：使用现有用户、凭据、Session 和审计表，无迁移，已发布迁移不修改。
- 套餐：账户安全管理不受商业套餐限制，设备与成员配额不变。
- 运维：正式部署仍必须启用 HTTPS；HTTP 调试环境不提供传输保密性。

## 验证计划

权限与租户隔离、CSRF、输入校验、当前密码校验、限流、会话撤销、持久恢复、
事务故障回滚及跨数据库连接的并发更新/登录/轮换测试；完整 Go 构建、vet、
测试及 race；前端 API 契约测试与真实浏览器自助操作验证。
