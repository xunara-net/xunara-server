# ADR-0012：认证存储故障与无效身份分离

- 状态：Accepted
- 日期：2026-10-09

## Architecture Change Proposal

代码梳理发现，SQLite 会话及 API Key 查询把所有扫描失败返回为“不存在”，
用户查询也只有布尔结果。HTTP 和 gRPC 因而无法区分真实的无效身份与数据库
故障；旧退出入口可能清除 Cookie 并报告成功，Web 启动则把读取失败当成匿名。
这违反失效与撤销必须以持久化事实为准的边界，也妨碍故障恢复。

## 决策

- 只有 `sql.ErrNoRows` 表示不存在；数据库、扫描及上下文错误保留错误链。
  用户存储增加带 context 和错误结果的读取，旧布尔读取仅作为兼容适配。
- HTTP、gRPC 复用相同身份解析，继续区分 Human Session 与 Service API Key；
  无效、过期、已撤销或已删除用户的凭据保持原未认证行为。
- 认证存储故障 fail closed：HTTP 返回不含内部错误的 503 和重试提示，
  gRPC 返回 Unavailable；不返回匿名快照，不清 Cookie，不报告退出成功。
  多个同名 Cookie 仍逐个验证，旧父域凭据不能遮蔽有效主机凭据。
- Web 启动将“尚不能确认身份”与“已确认匿名”分开，失败时显示可重试页面，
  不挂载账户功能，不把受保护地址改成登录地址；恢复后重新读取服务端事实。
- 不修改公开接口字段、数据库迁移、套餐、机器注册或 Tailscale 协议。

## 验证

验证真实数据库读取失败、取消上下文、不存在/撤销身份、同名 Cookie、
服务与人类身份边界、HTTP/gRPC 一致性、退出失败保留 Cookie，以及 Web 启动
故障后的恢复。执行完整 build、vet、test、race 和前端测试/构建。

上述验证已通过。隔离 Chromium 集成验收进一步确认：503 或格式不完整的认证
快照不跳转、不清 Cookie、不挂载账户页面；恢复后重试返回原受保护地址。
历史只读调用的布尔适配不在本次全面替换范围内，继续按调用点收敛。
