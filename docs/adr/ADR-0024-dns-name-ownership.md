# ADR-0024：设备、服务与记录的事务型 DNS 名称归属

- 状态：Accepted
- 日期：2026-10-10
- 提案：[DNS 名称归属](../proposals/2026-10-10-dns-name-ownership.md)
- 跟踪：[任务 #7](https://github.com/xunara-net/xunara-server/issues/7)

## 决策

机器自报 Hostname 与分配的 DNS label 分开。state 追加 v24，持久化分配名和租户
域名，FQDN 沿用官方 Node.Name。注册、轮换、MapRequest 和原生心跳共用 Store
写入；名称竞争在同事务内检查设备、服务和管理记录，冲突的新设备或更名自动使用
含节点 ID 的稳定后缀，不能覆盖已有记录，也不因重报相同主机名反复加后缀。

DNS 和服务写入反向复核名称归属，删除重复服务前置扫描。旧 UpdateNode 保留为
薄委托，指针型更新返回实际提交名；失败不发布候选事实。共享投影使用来源设备的
分配名，现有共享服务冲突检查统一尾点，避免绕过本地设备名保护。

旧无冲突名称在初次绑定中补录，保持 FQDN、IP、身份和原记录不变。旧重名或记录/
服务冲突失败关闭，不擅自更名。域名绑定后实例必须一致，不能用部署参数在线更换
命名空间。增加只读 CLI 预检，不应用迁移，不依赖 server-local 名称缓存。

## 备选方案

- 仅在 HTTP 层扫描：跨连接注册/更名与记录发布仍能同时通过，拒绝。
- 新设备重名即禁止注册：普通同名设备无法正常接入，采用安全别名而不是阻止连接。
- 改写自报 Hostname 或客户端协议：混淆机器事实与控制面名称，拒绝。
- 升级自动给所有旧重名节点换名：未经确认影响应用/证书/外部配置，拒绝。

## 兼容性与边界

无官方 wire 或管理 API 字段变更，无套餐、ACL、身份键或地址池变更。新增 Go
内部 DNSName 字段及 v24；旧二进制拒绝新库。更换已绑定域名需要另行受审迁移。
节点本地名称写入具有事务边界，不宣称整个注册/审计链路已经原子化，也不宣称
动态跨租户共享投影具有全局持久名称预留或全 OS DNS/宿主解析器已验收。

操作与验证见 [DNS 名称管理](../dns-name-ownership.md)。回退只能在维护窗口成套
恢复升级前状态和旧产物，恢复服务有新写入后禁止在线恢复旧快照。
