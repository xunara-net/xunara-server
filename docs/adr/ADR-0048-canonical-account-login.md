# ADR-0048 共享控制台统一账户登录入口

- 状态：Accepted
- 日期：2026-10-15

## 问题与决策

共享控制台的 `/t/<org>/login` 把普通登录绑定到 URL 中的租户，导致从旧书签、
退出登录或过期会话进入时，其他合法账户不能登录。共享部署统一使用 `/login`；
旧租户登录地址仅通过 GET / HEAD 临时重定向，不接收密码、不继续提供租户登录页。
未知或已删除租户的旧登录书签同样回到统一入口，不暴露租户是否存在。

已登录后的控制台和 API 继续使用租户路径与独立 Cookie。统一密码登录按当前
有效账户的唯一登录名定位，身份歧义或存储故障拒绝登录，不依据旧 URL、邮箱、
入口管理员会话或密码猜租户。退出仍先持久撤销当前租户会话，再返回统一登录页。

共享入口通行密钥先填写普通用户名，在对应账户的原身份库生成持久化挑战；
未知、禁用或不支持的账户使用入口的匿名挑战，响应不返回租户或用户信息。
挑战绑定仅保存在 HttpOnly Cookie，不携带租户标识。完成时重新解析账户，复用
原 WebAuthn 签名 / RP ID / origin / UV / 期限 / 浏览器绑定 / 单次消费验证，
并要求凭据实际持有人就是输入的账户。只有验证后的身份可以创建其租户会话。
旧单租户及独立 Host 的无用户名通行密钥流程保持不变；没有数据库迁移。

登录回跳只接受站内路径；普通页面去除旧租户前缀，再进入已验证账户自己的控制台。
设备 / SSH 授权等后端回跳保留范围校验，不能凭旧书签跳入另一账户的网络。
Human Session 不批准设备，不改变 Machine / Service 身份、TS2021 或原生客户端地址。

## 验证

覆盖已存在 / 已删除租户旧登录、退出、会话过期、换账户、用户名与密钥不匹配、
跨租户相同用户 ID / 凭据 ID、浏览器绑定、重放、禁用和限流。真实浏览器验证
统一密码及通行密钥入口，保留租户 Cookie 与 API 隔离、第三方及设备授权回归。
运行完整 Go build / vet / test / race、前端构建和 nginx 路由验收后部署。
