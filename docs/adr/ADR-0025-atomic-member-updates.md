# ADR-0025：事务型成员更新与所有者保护

状态：Accepted。日期：2026-10-11。

## 背景

见 [Proposal](../proposals/atomic-member-updates.md)。权限快照、目标读取、最后 owner
检查、用户写入和审计分开执行，无法保证跨进程竞争下的完整性。

## 决策

现有角色不扩展。JSON 与兼容 HTML 使用 Identity 的成员字段补丁事务，在事务内
验证实际发起会话或服务 key、当前 owner、目标版本和最后 owner，业务与审计一起
提交。CLI 使用仅限本地受信操作者的独立入口，复用相同补丁/不变量/审计逻辑。

updatedAt 是现有持久事实的版本，不另建本地缓存。管理读取新增该字段，Web 和
兼容表单原样提交 expectedUpdatedAt；冲突不会自动刷新版本并重放写入。未带版本
的历史 API 仍受事务授权和最后 owner 保护，但不承诺其具备客户端 CAS。

旧完整 User 更新作为薄适配，在已有时间戳时检查版本，不能拿旧元数据恢复角色；
低层删除在同一写事务内检查 owner，平台删除与成员降权不能共同移除最后 owner。

## 影响与边界

不涉及数据库迁移，不修改官方客户端 wire、ACL、节点身份、套餐或地址分配。
API 新字段为追加；邮箱仍仅是属性，不是身份键。存储/审计失败必须回滚；服务 key
范围只能收窄当前用户权限。无变更请求也验证凭据，不创建假变更审计。

本决策不等于细粒度 RBAC、全账户删除/恢复、第三方首次建号事务、平台审计原子性
或完整多实例发布已完成。多 owner 是 Xunara 既有规则，不改成 Tailscale 单 owner。
