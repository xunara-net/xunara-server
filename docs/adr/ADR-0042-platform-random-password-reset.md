# ADR-0042：超管直接重置随机临时密码

- 日期：2026-10-14
- 状态：Accepted
- Proposal：[超管随机密码恢复](../proposals/platform-random-password-reset.md)
- 替代：ADR-0031 的生成码 / 匿名兑换产品流程；原历史决策不改写。

## 决策

经过运营者明确核实和确认，平台管理员直接重置指定账号的随机临时密码，
旧密码和该用户全部人类会话立即失效。管理员不可读取旧密码，明文临时密码只
在本次成功响应展示；用户必须首次设置自己的密码，才能继续使用控制台。

恢复是显式授权操作，不根据邮箱属性或匿名请求提前改密 / 锁号。
新 API 的名字与确认信息明确「立即改密」，旧生成 / 兑换接口 410，不能静默换语义。
旧实现与表单删除，v17 表只保留给迁移 / 成套回退及旧码清理，不混用两条恢复链路。

Identity 追加 v19，现有账号标志默认 0、原密码 / 会话不变，作废旧待用码。
慢哈希后事务复核版本、用户启用与凭据，替换 bcrypt 哈希、强制改密标志、
旧码清理、会话撤销、用户版本及必需审计同事务。失败 / 忽略写入均回滚。

强制改密持久事实约束全部人类登录方式。HTTP / gRPC / 旧管理与设备审批入口
不能绕过，只开放本人改密及退出所需的最小账户表面。复用既有 CSRF、当前密码
验证与改密事务，成功清除限制并退出全部人类会话，再走正常登录，不自动授信。

## 兼容与后果

用户 / 登录响应新增改密状态；个人导出 schema v1 不变，后台显式识别新版重置模式。
套餐、state / plans、Machine / Service / Relay 身份、设备地址与客户端协议不变。
外部身份和通行密钥保留，独立服务凭据不因人类密码恢复而撤销；疑似泄漏要单独处置。

成套私有备份、停止旧实例后配套发布，不能混版读写身份数据库。
对外恢复业务写入后不可覆盖旧快照。不擅自恢复原生产账号，不宣称自动邮件找回、
可靠通知、完整 MFA 或全面接管恢复已完成。

与自助邮件链接相比，人工随机临时密码减少用户兑换步骤，但运营者必须安全交付
临时秘密；首次改密和独立核实不能省略。验证与运维以[服务端手册](../password-recovery.md)为准。
