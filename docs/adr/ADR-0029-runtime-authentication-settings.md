# ADR-0029：持久认证配置与注册职责分离

- 状态：Accepted
- 日期：2026-10-11
- 决策者：Xunara 开发维护者

## 背景

部署文件中的公开注册既决定独立网络开户，也被用于禁用成员邀请；提供方
只支持部署时配置，正式用户中心和平台后台没有管理入口。

## 决策

采用 [Proposal](../proposals/runtime-authentication-settings.md) 的持久版本化配置：
成员准入和公开开户分开；租户所有者管理本网络认证，平台管理员管理指定租户及
公开开户。配置写入、审计、待完成事务失效原子执行，认证提交核验配置版本。

运行时密钥只写不读、单独密封，提供方身份域不可变，出站请求拒绝非公网与
重定向。部署提供方保留明确来源，不能复用其 ID 指向另一身份域。已有身份、
设备、会话和邀请记录不因配置开关而删除。

## 备选方案

- 只增加提示或文档：没有正式配置入口，拒绝。
- Web 直接修改部署文件/读取环境密钥：越权及密钥泄漏风险，拒绝。
- 只在进程 Registry 中增删：重启丢失、实例不一致、旧事务混用，拒绝。
- 用注册开关统一改变开户与加入共享网络：破坏多租户隔离，拒绝。

## 影响

Identity 追加配置与事务版本迁移；新增管理 API。官方客户端协议、设备信任、
已分配网段和商业配额不变。备份必须包括状态目录密封密钥；真实 OAuth/OIDC
凭据及提供方可用性仍由运营者负责，配置页面不能替代应用申请。
