# 设备分享

## 用户操作

1. 网络所有者或管理员在「设备」列表或设备详情点击「分享」。
2. 输入接收人在本平台的用户名。只能选择另一网络的现存、未禁用且名字唯一的账户；不需要网络标识、第三方身份 subject 或令牌。
3. 接收人登录自己的用户中心，在「设备分享 → 分享给我」接受或拒绝。
4. 接受后自己的 Tailscale 设备可以访问这里列出的共享 IPv4/IPv6。无需换控制面、重新注册设备或共享密码。启用 MagicDNS 后也可使用完整 DNS 名称。
5. 分享方可撤销；接收方可移除。已拒绝/撤销的记录保留，再次分享需要新邀请。

只开放指定机器，不开放全网、子网、出口、设备配置或管理权限，也不增加真实设备用量。另一网络的其他成员看不到邀请和共享机器。共享机器默认不能主动连入接收人的设备，但可以回复接收人发起的连接；需要双向主动连接时由双方分别分享指定机器。访问同时受源网络 ACL、接收网络限制和设备防火墙控制，不自动扩大 ACL。控制面在线不代表某个应用服务可达。

普通账户禁用、删除、租户删除重建、节点 stable ID 替换都会使旧授权失效，不能凭同名账户或相同数字 ID 恢复旧权限。Noise 身份更换需要重新分享。启用 Tailnet Lock 的任一方暂不支持跨网分享；记录仍可撤销。

## 部署与升级

多租户路由器配置 `-platform-state-dir` 会自动启用 `shares.db`；不需要额外把平台管理令牌暴露给用户中心。单独运行的一个租户没有跨租户目录，接口明确报告未启用。

分享数据库 v2 追加实例/账户绑定与必需事件。v1 活跃分享无法证明实例边界，升级时保留记录但撤销访问，需重新发出。升级前停写并备份状态、数据库、Noise 私钥和二进制；回滚 v2 到 v1 必须在重新开放写入前恢复配套备份，不能只换旧二进制或覆盖已经接收新写入的数据库。

## 用户中心 API

全部路径基于当前租户控制台；例如 `/t/alice/api/v2/device-shares`。必须使用有效人类会话，写请求带 `X-CSRF-Token`，Service API Key 不能代替接受人。

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | `/api/v2/device-shares` | 分享能力、CSRF、本人收到的记录和管理员可管理的已发送记录 |
| POST | `/api/v2/device-shares` | JSON `{ "node": "stable-node-id", "recipient_login": "bob" }`，创建待接受邀请 |
| POST | `/api/v2/device-shares/{id}/accept` | 接收人接受 |
| POST | `/api/v2/device-shares/{id}/reject` | 接收人拒绝 |
| DELETE | `/api/v2/device-shares/{id}` | 有权管理来源的管理员或指定接收人撤销，重复撤销幂等 |

响应只在已接受且实例仍有效时返回接收网络中的共享地址，不返回对方真实内网地址、私钥或设备审批凭据。不存在/重名/禁用用户名统一报告接收人不可用，没有全局账号搜索。发送按当前会话账户限制为每小时 20 次，避免批量骚扰；失败、超时或版本冲突必须显式刷新实际结果，不能自动重试。

原 `/api/v2/shares` 的外部 `(provider_id, subject)` 接口仍保留，账户分享写入不能绕过新人类会话接口。旧 Cookie 写入现在同样要求 CSRF。

## 验证边界

兼容测试使用锁定版官方 Noise/TS2021 和有状态包过滤器，验证完整公开密钥、IPv4/IPv6 masquerade、共享隔离、quarantine 回复、ACL 不扩大和撤销。独立的 `integration/sharing` 测试启动两个真正的官方 tsnet 客户端和临时 DERP，在重叠的真实地址池中验证 IPv4/IPv6 TCP 请求与回复、共享方禁止主动访问接收方、撤销后实际连接失败。依赖仅在集成测试模块，不进入控制面运行时。

```sh
cd integration/sharing
go test . -count=1 -timeout 4m
go test -race . -count=1 -timeout 4m
```

浏览器验收覆盖真实多租户后端、用户名邀请、收件箱接受/拒绝/撤销、故障后显式刷新和手机布局：构建服务端及 Web 后运行 `xunara-web/scripts/device-sharing-browser-smoke.cjs`，以 `SMOKE_XUNARAD` 指定测试二进制，`PLAYWRIGHT_MODULE`/`CHROMIUM_BINARY` 指定浏览器。所有数据库、证书和账户均为临时隔离资源，不修改生产环境。用户实际网络的防火墙、端点可达性和自建中继仍需部署后实测。
