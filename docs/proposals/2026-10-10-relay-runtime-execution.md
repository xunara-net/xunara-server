# Architecture Change Proposal：中继运行时配置与执行回执

- 日期：2026-10-10
- 范围：Relay → Server → Web/Admin → Docs/Deploy
- 任务：https://github.com/xunara-net/xunara-relay/issues/1
- 前置：ADR-0020 的配置版本链、事务历史与审计

## 已核对数据流

服务端当前心跳仅保存遥测并返回期望配置，Relay 的回调仅打印版本；旧连接包装器
把大于 burst 的字节数截断，会漏计大包。已核对依赖 Tailscale v1.104.1 的
derpserver.Handler、Close、SetVerifyClientURL 和 ExpVar，以及 x/time/rate v0.16.0 的
WaitN/SetLimitAt/SetBurstAt。官方 wire 类型和握手保持原样，不复制上游协议实现。

## 决策提案

1. 始终追踪 TCP 连接，以同一每连接双向 token bucket 热更新限速；大包分段计费，
   重配置取消旧等待但不关闭连接。0 使用启动本地基准，-1 取消，正值覆盖。
2. online 允许新 DERP；maintenance 拒绝新 DERP但保留已有连接；disabled 关闭已有
   TCP 并拒绝新 DERP；revoked/删除身份属于终态。HTTP 探测不代表 DERP 可用。
3. 托管新进程先关闭 DERP 准入，必须成功联系控制面并实际应用配置后才开放。缓存只
   保存绑定服务身份的配置/版本高水位与撤销标记，不保存用户数据库或重新授权客户端。
   控制面暂不可达时保留当前配置及既有连接，上游准入仍失败关闭；重启不凭缓存放行。
4. 现有 config_version 仍是 opaque 等值 token；增加可选 config_revision，作为本平台
   的单调序号。兼容旧 Xunara 的规范十进制版本，无法确定序号的配置不猜顺序。
   同版本异内容/较旧版本拒绝，成功后幂等；应用/缓存失败可重试，不能提前记成功。
5. 心跳新增可选 execution（尝试版本、已应用版本、状态、实际状态/限速、固定错误码）。
   无回执的旧 Relay 仍被接受，但当前执行事实为未知。回执是服务身份上报，不是独立
   数据面验证；收到期望版本不等于成功执行，失联回执不能冒充实时事实。
6. state 只追加 v22 的执行报告与服务端接收时间；心跳按 token hash 选择本租户服务，
   在事务内复查身份/撤销与版本，提交遥测和回执。回执事实变化的成功审计同事务提交，
   临时数据库故障返回 503，不误当成撤销。平台凭据/人类会话不能替代服务身份。
7. 终态认证响应使新 Relay 持久记录撤销并关闭数据准入；缓存写失败也先停止数据面。
   秘密不进入 URL/argv/日志，未知错误响应不直接打印到日志。

## 兼容与恢复

只扩展 Xunara 服务管理 JSON，旧双方忽略未知可选字段；不改 TS2021/Noise/DERP/STUN、
节点/人类身份、套餐或 Headscale。先发布服务端再发布前端/托管 Relay；现有静态
公共 Relay 不改配置或重启。v22 使旧服务端拒绝新库，回退必须在恢复公网写流量前
成套恢复旧产物与完整一致性状态，不能降版本号/删列或在线覆盖旧快照。

## 验收

构建/vet/全量/race；大包真实读写、热更/取消等待、维护保留与停用断开、严格 TLS pin
下官方 derphttp 转发；缓存损坏/身份不匹配/版本重放/应用失败重试/终态认证；服务端
事务故障回滚、旧 Relay/新 Relay 兼容、租户/身份边界、迁移/重启；两个前端的真实
回执/未知/待执行/失败与手机交互。生产只读检查，故障与测试身份仅在隔离环境使用。
