# Proposal：中继注册的事务边界

- 日期：2026-10-09
- 范围：租户中继注册；不改变数据库结构、身份模型及客户端协议。

## 问题与数据流

现有注册先消费一次性令牌，再读取中继数量，最后创建长期服务身份。配额拒绝、
存储故障或重复节点会让令牌被提前消耗；不同令牌的并发注册可以一起通过数量检查。
进程本地互斥不能解决多个数据库连接的竞争。

## 最小决策

在 `state.RelayStore` 增加唯一注册写入口：同一事务内验证令牌、核对当前资源数量、
插入中继及凭据哈希、标记令牌使用。平台从 Entitlement 读取额度并传入，不让存储层
依赖套餐名称。SQLite 使用既有 `BEGIN IMMEDIATE`，内存实现使用同一锁；任何失败
不消费令牌、不创建身份。移除只有“消费令牌”的旧写入口，避免业务继续两步提交。

注册前的凭据读取增加带 context 的错误返回，未知凭据与存储故障分开；事务内再次
验证，不能依赖之前的读取。HTTP 接口沿用既有成功字段及 401/403/409/410 错误码。
有效凭据遭遇查询故障时失败关闭，返回不含数据库细节的 503。

## 兼容与未覆盖边界

不修改迁移、现存记录、心跳、准入、DERP 数据面或官方 Tailscale wire 协议。
`CreateRelay` 保留为底层记录写入/测试夹具，产品注册只能调用事务入口。
注册后的审计沿用现有控制面审计路径；本提案不把它改为事务审计，也不宣称解决
提交后响应丢失的身份恢复、套餐变更与注册的跨模块竞争，以及所有资源的配额原子性。
这些仍须独立设计和验收。

## 验证要求

两种存储实现覆盖未知/过期/重放令牌、零/有限/无限额度、重复节点、失败回滚和
取消 context。两个独立 SQLite 连接并发注册必须遵守相同额度；同一令牌只能成功
一次。真实 HTTP 回归检查配额拒绝后令牌可重试、跨租户拒绝、存储故障失败关闭。
执行 build、vet、全量测试与全量 race，不跳过既有兼容测试。
