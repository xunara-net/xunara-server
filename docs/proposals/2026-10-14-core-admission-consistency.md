# 设备接入与核心一致性修复提案

## 问题与范围

独立租户网页可使用入口主机的组织路径，但原生客户端仍按 Host 路由。共享入口
不能隐式选择入口 owner 的网络。浏览器审批目前分开提交节点、授权决定与审计；
文件策略、应用 Grants 的实际 IPv4 地址及平台注册表迁移也需统一安全边界。

先修复上述核心链路，不转移已有设备、不合并账户、不更换 Noise 或 TLS 密钥，
不把 UI、OAuth transaction 或浏览器 Cookie 作为机器信任依据。

## 设计

- 审批事务在获得数据库写锁后复核发起凭据、角色、待审批状态和精确机器/节点键；
  创建或合法轮换节点、设备额度、授权决定、必需审计及通知版本同提交。拒绝操作
  同样持久化决定与必需审计。内嵌管理调用与网络人类/服务请求明确区分。
- 所有生产策略来源使用严格字段/重复键检查；未支持的限制条件拒绝加载。
  应用通配 Grants 保留标准地址语义，只追加实际本租户节点的非标准单主机地址。
- 平台组织/套餐迁移的 DDL 与版本标记同事务，数据库写锁内重新读取版本，
  避免两个启动连接重复迁移。不修改已发布的迁移 SQL。
- 可选共享原生入口由平台适配器负责选租户。未知设备通过普通账户登录确认，不要求
  用户填写网络标识或选择登录范围，不能
  复用入口管理员会话；持久路由绑定只决定处理范围，不授予机器信任。浏览器
  授权仍在目标租户自己的会话/CSRF/审批事务内完成。
- 共享入口复用原入口 Noise 密钥，所有内层端点都按精确 MachineKey/NodeKey
  与目标组织处理；路由提示不是身份凭据，歧义、存储故障及删除的组织失败关闭。
  独立 Host 部署保持原行为，不使用浏览器路径冒充客户端协议路径。

## 验收

审批决策/审计/通知故障零部分节点，跨连接竞争不重复或超配额；已注册节点
精确键绑定与轮换身份不变。严格策略文件/数据库入口对等，非标准地址应用
CapGrant 不扩大到其他租户。中途迁移失败可再次正常启动，旧 SQL 保持不变。
共享入口使用真实上游 TS2021 传输验证双租户、旧入口会话、浏览器授权、Token、
Map/DNS/ACL/DERP、辅助端点、重启及错误键；未完成此验收前不宣称线上接入修复。
