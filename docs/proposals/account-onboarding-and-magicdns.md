# Proposal：可用的 MagicDNS、第三方绑定与邀请准入

## 问题与数据流

当前 DNS 配置有完整下发底座，但空部署域名使用户无法启用。OIDC 登录会给未知身份隐式建成员，缺少当前账户绑定、解绑与邀请注册。密码邀请已经可用，不重写它。

## 本次边界

- 空域名的网络可由管理员显式初始化一个稳定、独立的内部域名；名称归属、DNS 配置、版本、审计同事务提交。初始化不改 IP，不重命名设备，不开放公网 DNS 或证书。既有域名不可改；重启从持久命名空间恢复，关闭 MagicDNS 通过配置开关完成。
- 基础 MagicDNS 不依赖自定义 DNS 套餐权限；修改解析器、搜索域、分流规则和自定义记录仍受 Entitlement 控制。
- OIDC 绑定必须是当前人类会话加 CSRF 发起，并以持久认证事务引用发起用户和会话；回调复核同一浏览器、同一有效会话及提供方身份。绑定不创建用户、会话或设备，不按邮箱合并。
- 解绑必须同事务检查至少保留一个当前部署可用的认证方法；同一提供方的登录会话一并吊销。绑定、解绑和登录必须有必需审计，失败回滚。
- 新增 OIDC 邀请注册：邀请码只经 POST body，事务只保存哈希；回调重新检查邀请有效性、角色和实际成员额度。已绑定身份可以登录，但不能用邀请修改角色。未知身份只有 open 模式或有效邀请可建成员；自助开租户入口继续禁止隐式共享成员。
- 追加 identity v14，仅为认证事务增加用户/会话引用与邀请哈希。不修改已发布迁移、Tailscale wire types、Noise、设备审批和三种身份边界。
- 本次不宣称交付全局账户跨租户成员模型、邮箱投递、密码找回或真实外部 IdP 的部署配置。

## 验证与回退

覆盖首次初始化、CAS、名称冲突、权限、套餐、重启、官方客户端 DNS；覆盖绑定与解绑、提供方碰撞、邮箱不合并、会话吊销、最后登录方法、并发邀请、撤销/过期/额度、审计失败和旧 schema 升级。运行全量 build/vet/test/race、前端测试和真实浏览器流程。上线前完整停止写入并备份；旧二进制不得直接打开新 identity schema，回退使用完整旧状态。

## 上游依据

- [Tailscale MagicDNS](https://tailscale.com/docs/features/magicdns)，并核对锁定的 tailscale.com v1.104.0 DNSConfig/客户端处理代码。
- [OIDC Core](https://openid.net/specs/openid-connect-core-1_0.html)，复用 go-oidc v3.21.0 与 oauth2 已有校验，不自制协议或按邮箱绑定。
