# Proposal：密码登录的存储故障与旧入口收敛

- 日期：2026-10-09
- 状态：Accepted（落地决策见 [ADR-0016](../adr/ADR-0016-password-login-consolidation.md)）
- 延续决策：[ADR-0012](../adr/ADR-0012-authentication-storage-failures.md)

## 问题与调用链

继续核对发现，JSON 密码登录和旧 HTML 密码登录各自保留限流、账户读取、密码验证、
会话签发和审计代码。两处在限流存储失败时都继续认证；账户与凭据布尔读取把存储
故障当成错误密码，初始化数量读取又可能把故障当成未初始化。这些行为与已经接受
的认证失败关闭决策不一致，不能以正式 Web 不再使用 HTML 为由保留旁路。

调用链为 POST 入口 → 初始化状态 → IP/登录名持久限流 → 账户/本地凭据读取 →
bcrypt 验证 → `CreateLocalSession` 的事务型哈希复核 → 会话 Cookie。用户和凭据查询
必须带请求 context；官方客户端协议与机器授权不在本 Proposal 范围。

## 最小方案

1. 为登录名、凭据和本地凭据数量增加有错误结果的 context 读取。只有无记录对应
   不存在；保留旧读取为薄适配，不复制 SQL，不修改表结构或已发布迁移。
2. 新旧密码 POST 共用限流、凭据验证、事务型会话创建及审计调用。错误密码、未知
   用户和无本地密码仍返回同一 401，并保持实际 bcrypt 工作量。
3. 限流、初始化数量、身份读取或会话存储故障返回脱敏 503 与重试提示，不签发或
   清理 Cookie、不跳转初始化、不继续密码验证。新旧入口共用原持久预算。
4. HTML 的表单 CSRF、成功回跳以及 API 的 JSON 成功载荷继续由原适配层处理。
   不改套餐、提供方策略、设备审批或会话撤销语义。

## 验收

先通过真实 SQLite 写入/读取故障复现旧行为，再实现修复；不得在启动后台任务后
替换 Store 指针，也不得降低哈希强度或跳过测试。核对故障时的零新会话、旧登录
保留、秘密脱敏、故障恢复、共享限流、统一错误密码及取消 context。
执行 build/vet/全量 test/race、定向重复和最终发布产物的浏览器回归；CI 全绿后
才做保留租户、配置和回滚快照的升级。

## 边界

本地成功登录审计仍沿用已有提交后调用，不在此宣称已与会话原子绑定。
启动初始化、其他旧读取、第三方首次建号和全局账号生命周期仍须按调用点审查。
此修复只落地已有失败关闭决策，不改写 Accepted ADR 或权威规格。
