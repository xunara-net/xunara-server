# Architecture Change Proposal：用户地址管理与非托管中继

- 日期：2026-10-10
- 范围：Server / Web / Admin / Relay / Deploy / Docs
- 跟踪：[跨仓任务 #5](https://github.com/xunara-net/xunara-server/issues/5)
- 前置：ADR-0005、ADR-0021；state v22 / identity v13

## 已核对缺口与 upstream

网段目前只有平台管理员接口，而且只影响新设备；用户页面要求联系管理员。设备
IPv4 没有修改接口。默认中继藏在第二个标签，非托管 DERP 没有持久配置入口，
托管 Relay 没有按系统/架构提供已发布二进制下载。

已核对依赖版本 Tailscale 的 tsaddr、tailcfg.DERPMap、controlclient netmap 合并、
现有 Mapper 和 MapSession。官方设备 IPv4 只使用 100.64.0.0/10 的子集；
100.100.0.0/24、100.100.100.0/24、100.115.92.0/23 是上游保留段，另须排除
Xunara 分享地址及部署保留段。规格中的 192.168.50.0/24 不得直接作为官方客户端
设备地址；它仍可用于子网路由。该兼容边界先记录提案，不为 UI 修改 wire。

来源：[IP pool](https://tailscale.com/docs/reference/ip-pool)、
[Headscale FAQ](https://headscale.net/stable/about/faq/)、
[DERP](https://tailscale.com/docs/reference/derp-servers)。

## 决策提案

1. 网段提供读取、校验预览与带基准版本的保存；同一权限/能力/保留段/冲突路径供
   用户中心和超管调用。Free 保持不可编辑，不硬编码套餐名称。保存改变后续设备的
   分配范围，旧设备不静默重编号；用户在设备详情显式修改 IPv4，预告连接中断。
2. state 只追加持久地址配置，分配与手动改 IP 在事务里读取实际范围；检查地址
   占用、范围、保留地址与旧 IP 基准，修改只写地址列，不覆盖运行中节点其他属性。
   用户身份复查、地址变更、审计和配置通知同一事务提交。
3. 平台只追加网段预留/版本记录。变更保留旧范围，避免旧设备还在使用的地址被
   另一租户分走。平台期望范围与实际分配范围分别表达；跨库应用失败不得返回
   已生效，保留两侧预留并支持重启/重试收敛，不在线恢复旧快照或复活旧版本。
4. 默认/部署中继直接展示。新增非托管中继配置与官方地图导入；外部节点没有服务
   身份、心跳或远程控制能力，不伪造在线、执行回执、带宽或套餐遥测。
5. 外部地图保存在现有租户配置/历史事务中，与部署地图、本租户托管地图严格合并，
   不覆盖默认地区、串租户或绕过部署 DERP policy。地区 ID 冲突拒绝；删除最后一项
   使用明确空地图，不把 nil 当作删除。
6. 官方导入仅访问固定 HTTPS 官方地址，限制响应大小、超时和重定向；其它地图
   通过手工配置导入，不允许后台任意 URL 抓取。保留完整节点/端口/TLS pin。
7. 托管中继下载必须对应真实发布产物：常用 Linux/Windows/macOS 架构交叉编译，
   生成 SHA-256，发布到实际组织 xunara-net。交叉编译不冒充各 OS 现场运行验收，
   不提供尚不存在的下载地址或未实现的自动升级/签名保证。

## 兼容、恢复与验收

不修改 TS2021/Noise、MachineKey/NodeKey、人类/服务身份、官方 DERP/STUN wire、
套餐定义或 Headscale。IPv6 暂由系统分配，RFC1918 为子网路由；已有不兼容网段
不自动改写，UI 明示。旧中继仍可用；默认静态节点不擅自迁入托管或重启。

完整 Go build/vet/test/race；网段/IP 角色、CSRF、额度、冲突、并发、取消、审计
失败与重启；官方 MapResponse 自身/peer/DNS/过滤器地址更新回归；非托管地图
导入、合并、政策、跨租户、故障与持久化；前端单测/构建/手机浏览器；多平台
编译与发布文件校验。上线前完整维护备份，只读验收，不在生产造测试节点。
