# Proposal：路由与出口管理闭环

日期：2026-10-12。状态：已接受，见 [ADR-0037](../adr/ADR-0037-route-management.md)。

## 范围与理由

路由页目前仅展示列表，审批必须跳设备；旧路由写入先读后覆盖、审计与配置版本
不在同一事务，客户端遥测旧快照也可能覆盖审批。继续优先网络核心，不扩充支付
或外围账户入口。参考官方 Tailscale 路由注入/子网文档和本仓库固定依赖的
AllowedIPs/PrimaryRoutes；审批不等于 ACL、转发、防火墙或真实端到端可达。

## 决策与数据流

- 新增租户路由总览、单设备路由配置及版本保护的审批管理 API；只读白名单、有界
  输出、失败不冒充空列表，明确宣告、批准、已撤回、离线/过期与配置交集。
- 版本是节点稳定身份/密钥/归属及宣告和审批的不可逆摘要，不返回密钥。新接口
  强制版本和当前宣告校验，冲突保留草稿，不隐式重试或批准不存在的路线。
- 审批差量、持久角色/会话/服务 key 复查、必需审计、配置版本同 SQLite 事务。
  只更新批准字段，不覆盖设备密钥、地址、Hostinfo 或身份。取消可用于套餐降级
  清理；新增批准仍执行 Entitlement，不使用套餐名称分支。出口与子网开关独立。
- 旧 v1/HTML 路由写入委托同一核心流程，保留旧差量/响应和预批准兼容语义，
  不留两份不一致审批业务；正式写入依赖现有持久网络配置模块，不能退回非原子
  内存分支。客户端遥测更新保留事务内最新审批，防旧快照回写。
- 路由页可以搜索/筛选/分页，直接打开审批和预览确认；设备页复用同一组件。
  手机详情和弹窗不横向溢出，读取失败、保存失败、并发修改各自可见。
- 出口显示真实已批准节点及客户端自报选择（不是活跃连接证明），从控制台给出
  本机选择命令但不伪造远程修改客户端。审批默认路由不代表客户端自动启用出口。

## 兼容、安全与验证

不新增迁移、不改官方 Register/Noise/Map/DNS/DERP 或路由选举/故障转移算法。
复用现有 CSRF、write scope、API Entitlement、事务内 CheckNetworkWriter。
新 API 约束不会写入 v1 的可选协议字段或改变客户端 wire。

验证事务 ABORT/IGNORE 回滚、版本/节点替换/两连接并发、角色撤销/降权/跨租户、
新旧入口一致、套餐独立开关/降级清理和遥测快照；官方 Noise 下发批准/撤销
AllowedIPs/PrimaryRoutes，Web 类型/单测/手机真实 API 浏览器回归，Go 全量
build/vet/test/race。保留“配置就绪不代表真实可达”的边界，不宣称实时路径或
全 OS 出口现场验收；若上线则私有一致备份并保持原用户、地址和默认 Relay。
