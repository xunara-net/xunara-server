# 公开开户用户名唯一与用户默认网段

## 问题

公开开户把用户名转换为组织域名前缀；组织 ID 冲突时直接追加随机后缀，
因此同一用户名可以反复开户。租户内部的用户名唯一约束无法保护平台入口，
IP 限流也不是用户名唯一性的替代品。

用户已明确要求本人管理默认设备网段。目前默认池可修改，但切换附加池为默认
缺少明确入口，而且调试部署的 Free 配置尚未开放自定义网段权限。

## 方案

1. 组织注册表只追加 v2 迁移，新增公开开户名称占用表，用户名按 ASCII
   大小写不敏感唯一。名称占用和组织记录在同一 SQLite 写事务内提交，不能
   使用服务进程内的锁或先查后写作为唯一性保证。
2. 路由器启动前从已有租户的人类用户名补齐占用；发现旧同名账户只保留
   现状、阻止继续开户，不自动合并、删除、重置密码或决定登录归属。
   名称表不是身份表，不按邮箱合并，不用于认证或机器路由。
3. 同名公开注册返回 409 / LOGIN_NAME_TAKEN，无新组织、会话、套餐或网段。
   只有不同用户名恰好映射到同一个组织短名时才允许组织 ID 使用随机后缀。
   校验拒绝超长或会被字符过滤改变的用户名，不悄悄替用户改名。
4. 初始化失败时，确认新组织已退出且注册表已移除之后，才释放该次请求的
   名称占用。清理失败、断连或提交结果不确定时保留占用、返回可用性错误，
   避免重复开户。正常删除保留名称墓碑，避免旧链接与已归档身份被复用。
5. 用户中心明确区分默认网段和附加网段。选择「设为默认网段」时把原默认池
   留作附加池，经原预览 / 版本 / CSRF / 权限 / Entitlement / 审计链路保存。
   新设备使用新默认池，已有设备 IP、ACL、DNS 和路由不自动改变。
6. 按本次用户要求，调试部署通过持久套餐配置为 Free 开通自定义网段；
   Free 10 台设备及其它额度不变。程序不绕过 Entitlement，也不把套餐名
   判断写入 Core；其它部署的内置套餐默认值不变。

## 边界

租户内部成员邀请、OAuth/OIDC 身份键、已有会话和平台管理员身份不变。
单域正式证书并不覆盖旧 nip.io 客户端地址；名称和默认池修复不能冒充共享
TS2021 网关已经完成，不能把主域名随意发给独立租户客户端而接入错误网络。

## 验证与恢复

覆盖同名重试、大小写与空白、并发 / 两个数据库连接、重启与旧同名账户、
失败回滚、独立短名碰撞、取消及数据库错误；默认池切换覆盖新设备分配、
旧 IP 保持、陈旧版本 / 越权拒绝与标准 MapResponse。Go 全量 build/vet/test/race，
Web 类型 / 单测 / 构建和隔离浏览器回归。正式升级停止写入并完整备份，
先发布 Server 再发布 Web；公开写入恢复后禁止旧快照覆盖新数据。
