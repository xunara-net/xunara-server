# Proposal：初始化与自助租户 owner 的原子认领

- 日期：2026-10-09
- 状态：Accepted（落地决策见 [ADR-0017](../adr/ADR-0017-atomic-owner-bootstrap.md)）
- 延续：[ADR-0007](../adr/ADR-0007-self-service-tenancy.md)、[ADR-0012](../adr/ADR-0012-authentication-storage-failures.md)、[ADR-0016](../adr/ADR-0016-password-login-consolidation.md)

## 问题与数据流

初始化与自助开租户都调用 `claimLocalAccount`，但它分别更新用户、写入密码；会话
和审计又由各 HTTP 调用方单独提交。写入失败会留下不能重试的半初始化账户，两个
实例同时通过初始化检查还可能互相覆盖 owner。文件令牌删除不能充当数据库的一次性
提交边界；密码后来被删除也不应重新开放初始化或把它变成密码重置接口。

启动、公开认证元数据、旧 HTML 注册与成员邀请仍调用隐藏数据库错误的初始化计数。
初始化与平台自助注册的限流失败还会继续执行业务，必须延续已有失败关闭决策。

本次调用链：启动初始化状态 → 文件证明 / 请求限流与 CSRF → 密码校验和慢哈希 →
租户身份事务（一次性状态、内置 owner、密码、会话、必需审计）→ 文件清理 / Cookie。
自助开租户继续经 Router、Entitlement 和既有组织回滚，不把身份事务与平台多个
数据库伪装成一个全局事务。

## 最小方案

1. 只追加身份迁移 v13，持久记录本地初始化已完成的事实。升级时根据已有本地凭据
   或明确的初始化 / owner 注册审计回填；不改已有用户、密码、身份链接或迁移条目。
2. 初始化状态采用带 context 的类型化查询；读失败返回脱敏 503，不假报未初始化、
   不跳转、不改变 Cookie。启动无法确认状态或安全保存文件令牌时拒绝启动。
3. 内置 owner 认领、密码、会话及成功审计在同一写事务提交；在事务中取得一次性
   名额后复核 owner。失败全回滚、允许重试；重复认领不能更新密码或资料。保留原
   owner ID、既有外部身份键及机器归属，不增加占用 Free 成员名额的第二个账户。
4. 初始化与自助开租户共用该事务，删除原分步认领和会话 / 成功审计旁路。完成后的
   文件删除仅为清理，即使失败或留下旧令牌，数据库事实也必须阻止重放。
   自助开通补偿在组织成功退出后释放套餐 / 网段分配，避免失败开通泄漏地址池；
   使用有超时且不继承请求取消的清理 context，补偿失败明确记录待恢复状态。
5. 初始化与自助开租户的持久限流错误直接终止；注册、公开元数据及成员邀请门禁
   收敛为同一个初始化状态读取，保留正常载荷、注册模式和既有额度规则。
6. 升级跨越 v13 后旧服务端不能直接打开新状态；部署必须先验证并保存一致性备份，
   失败时在未恢复公网写流量前恢复原版本与完整状态。不得只回退二进制或在线覆盖
   已接收新业务的数据库。

## 验收

先以真实 SQLite 复现初始化限流放行、元数据假判断、密码 / 会话 / 审计故障后的
半初始化，再验证所有写点回滚和恢复、两个连接竞争唯一 owner、令牌重放、密码
删除后不重启初始化、旧状态迁移与重启、文件异常、取消请求、秘密脱敏和旧 Cookie
保留。执行定向重复竞态、build / vet / 全量 test / race、前端和最终产物浏览器
回归；对应提交 CI 全绿后才升级并做只读验收，不在生产注入故障或创建测试账户。

## 边界

不改公开 API 字段、机器身份、设备审批、TS2021 / Noise / Map / DNS / DERP 协议，
不更改套餐额度或 Headscale 架构决策。成功密码登录、第三方首次建号、初始占位
用户播种、平台跨库可靠补偿和完整恢复策略仍需单独收敛，不宣称全部认证已完成。
缺失旧凭据且没有完成审计的历史状态无法从不存在的数据推断初始化事实，需要
运维核对；不通过猜邮箱、用户名或设备身份来恢复人类身份。
