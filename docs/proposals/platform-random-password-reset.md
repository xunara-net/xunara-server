# Proposal：超管直接重置随机临时密码

- 日期：2026-10-14
- 状态：Accepted（用户明确要求）；实施与验证中
- 范围：Identity → Control / Admin / Web → Docs

## 原因

人工恢复不应要求用户另行兑换短效重置码、区分网络入口和两次提交。
改为超管核实持有人后立即重置随机临时密码；管理员不能读取旧密码，
用户首次登录必须换成自己设置的密码，不能把管理员见过的密码长期使用。

## 决策

1. 新增明确的随机密码重置 API，不把原「生成码但不改密」接口悄悄改为立即改密。
   旧生成与兑换入口返回 410，不再提供重置码表单；旧版客户端必须升级。
2. 仅平台授权能操作指定租户、指定启用且已有本地密码的账号。要求持有人核实声明、
   管理原因和完整用户版本；不按邮箱找账号，不为第三方专用账号添加密码。
3. 服务端使用 crypto/rand 生成 24 字节随机值（32 个 URL-safe 字符），慢哈希在事务外。
   写事务复核账号、凭据及 CAS 版本，原子替换 bcrypt 哈希、标记必须改密、
   作废旧重置码、撤销该用户所有人类会话并写必需审计。忽略写入也必须回滚。
4. 只追加 identity v19 的持久改密标志；已有账号默认无需改密，已发布迁移不回写。
   旧码表保留兼容升级与成套回退，但不开放新旧恢复流程并行操作。
5. 临时密码登录仍用现有密码认证和持久 Session。必须改密状态限制人类 HTTP / gRPC
   和旧管理 / 设备审批入口，仅允许查看本人账户 / 会话、改密码和退出；
   前端跳转不是权限边界。第三方或 Passkey 新登录也不能绕过此限制。
6. 复用本人改密 API 验证临时密码、新密码及 CSRF；成功原子清除标志并撤销全部
   人类会话，要求以新密码正常登录。不得自动授信设备或撤销独立机器 / 服务身份。
7. 新密码仅在本次 no-store / no-referrer 的管理响应显示一次，关闭 / 离开清除。
   不进入 URL、日志、审计或浏览器持久存储。结果未知不得自动重试；刷新版本、
   重新核实并显式确认后可再次重置，旧临时密码随之失效。
8. 此流程不是全面账户接管恢复，不删除 Passkey / 第三方绑定、API Key、设备接入 Key，
   不改变网络、套餐、节点或官方客户端协议；管理员须单独核查可疑凭据。

## 验证与上线

覆盖旧库升级、跨连接 / 重启持久化、跨租户、角色 / 服务拒绝、版本竞争、
改密 / 登录 / 禁用竞争、事务失败 / 忽略写入回滚、旧会话失效与强制改密绕过。
执行 Go build/vet/test/full race、前端单测 / 构建和隔离真实浏览器验收。
不擅自重置生产用户；维护升级须停止旧控制面、成套备份、源码与前端配套发布，
开放写入后不能用旧快照覆盖业务数据。

## 参考与兼容

- 规格允许人工管理员恢复，但不允许默认知晓用户密码；临时密码限于显式恢复，
  最终密码由用户自行设置。
- [OWASP Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)
  与 [Forgot Password](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)：
  恢复为高风险动作、独立渠道核实、安全存储、正常登录及会话撤销。
- 不修改 Tailscale TS2021 / Noise / Register / Map / DNS / DERP，Human / Machine / Service 分离。
