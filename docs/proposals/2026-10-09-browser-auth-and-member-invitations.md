# Proposal：正式 Web 认证入口与成员邀请事务

- 日期：2026-10-09
- 范围：人类账户登录、成员邀请与本地注册；不改客户端协议和租户模型。

## 问题与数据流

同源代理把 GET `/login` 交给 SPA，而提供方起始地址仍指向这个页面，第三方按钮
无法进入后端认证事务，也未保留设备授权等回跳目标。本地注册先创建账户、密码与
身份链接，再兑换邀请；补偿删除不是数据库回滚，并发申请可共同通过成员额度检查。
现有邀请只在旧 HTML 控制台提供，角色和存储故障边界不适合直接复制到新 Web。

## 最小决策

1. 增加 API 路径下的浏览器认证起始入口，复用现有 OIDC 事务和回调。回跳只允许
   站内路径；固定的 OIDC redirect URI 不从请求输入获取。旧登录书签保持兼容。
2. 本地注册在租户身份库同一事务内核验邀请与当前成员数量，写入账户、密码哈希、
   `(local, login)` 链接、邀请使用记录、会话和审计。任何步骤失败全部回滚。
   密码哈希在事务前计算，额度由 Entitlement 传入，不让存储依赖套餐名称。
3. 邀请创建与撤销只允许有效的 owner 人类会话，并在写事务内复核会话与角色。
   邀请不可授予 owner，明文仅在创建响应展示一次，不放 URL、浏览器持久存储或日志。
   列表读取返回存储故障，不伪装成无邀请。旧控制台入口复用相同业务实现。
4. 移除先创建再补偿的旧注册实现和独立兑换写入口，不保留并行注册规则。

## 兼容、安全与验证

不修改已发布迁移；既有身份、邀请和会话保持有效。新入口不改变 TS2021/Noise/
Register/Map/DNS/DERP；不会把第三方身份或邀请转为可信设备。邀请不预占成员名额，
兑换时再次检查额度；套餐切换与身份库之间的分布式事务不在本次边界内。

验证包括状态/回跳与浏览器绑定、真实 OIDC 签名和 PKCE 的同源 SPA 浏览器流程；
邀请的权限/CSRF/过期/重放/跨租户；注册各写入点失败回滚、审计失败回滚及两个
SQLite 连接争夺最后成员名额。完成后运行 build、vet、全量 test/race、Web 测试与构建。
