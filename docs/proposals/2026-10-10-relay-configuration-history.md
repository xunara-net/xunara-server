# 中继配置版本保护与历史恢复提案

## 问题与边界

用户中心和平台后台直接覆盖中继期望配置，两个窗口可能相互覆盖；写入后追加审计
也可能留下没有审计的配置。配置版本已经存在，但尚未作为操作前置条件。

本切片只管理期望配置，不改官方 DERP、STUN、Noise 或 Relay 心跳协议，也不把
“心跳获取配置”描述成已确认执行。当前 Relay 的心跳回调只记录配置，运行时限速和
停用执行仍需独立切片，不能用本次历史记录冒充完成。

## 方案

- PATCH 必须带当前 `config_version`，DELETE 必须带 `If-Match`；缺失返回 428，
  冲突返回 409，不自动重试或覆盖。
- 复用已经发布的 `network_document_history`，以 `relay:<id>` 为本租户历史键；
  不改已发布迁移，不新增重复配置头，权威当前值仍在 `relays`。
- 首次修改保存原始快照和新版本，历史最多返回最近 50 项；恢复也是新版本。
- 历史只含期望状态、带宽和地区显示名，绝不包含密钥、令牌、证书或遥测。
- 用户事务复查持久 Session/API Key 和管理员角色；平台使用独立令牌门禁，明确
  记录平台来源。配置、历史、审计和配置通知版本同事务提交，失败全部回滚。
- 删除复查版本并原子撤销服务身份、移除对应配置历史和写入审计；历史恢复不能
  重建已删除的中继身份。
- 已撤销身份不能通过历史恢复再次启用；持久 API Key 范围沿用既有逗号分隔格式，
  修正事务鉴权误读 JSON 导致有效自动化写入被拒绝的问题，拒绝未知范围。
- 两个前端保留冲突草稿，提供显式重新读取、历史查看和二次确认恢复。

## 验证与兼容

覆盖跨连接竞争、降权/撤销、租户隔离、坏字段、审计/历史/通知写入故障、取消请求、
重启与历史恢复；浏览器验证两个后台的冲突和恢复操作。旧操作客户端必须升级为
带前置版本，查询和 Relay 心跳响应保持兼容。涉及 Go 变更执行 build/vet/test/race。
本切片无数据库迁移；现存服务身份、证书 pin、静态公共地图与套餐额度保持不变。
