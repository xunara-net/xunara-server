# Proposal：独立平台身份与多通行密钥

状态：按本轮用户需求实施。范围限定为单一部署运营者，不冒充多管理员 RBAC。

## 问题与决定

后台此前只有部署令牌，没有独立人类会话。不得把任何租户 owner、Passkey 或
同名账号提升成平台管理员。新增独立平台 SQLite 文件，复用已有身份存储与
go-webauthn 验证器；平台令牌只作为首次登录及恢复入口，浏览器换取四小时的
可撤销会话。自动从第一个配置租户的公网 URL 推导固定管理员 origin，允许显式配置。

通行密钥挑战、浏览器绑定与平台会话相互独立。注册绑定发起会话，支持多个
凭据；解绑同事务撤销全部 Passkey 平台会话，未配置恢复令牌时保护最后一把。
普通租户身份、机器/服务身份和官方客户端协议均不改变。

用户管理新增“添加用户”：明确选择已有网络，账户、密码哈希、本地身份、
成员额度与必需审计同事务提交，不代用户登录、不开新网络、不自动信任设备。

## 替代方案与边界

拒绝复用默认租户身份、以用户名/邮箱判断平台权限，以及把永久令牌返回给
Passkey 登录者。暂不提供多个运营者账户、平台 OAuth、TOTP 或独立人身份恢复。
SQLite 多连接竞争可验证，但不等于完整多实例部署验收。

## 验证与回退

覆盖挑战重放、浏览器/会话/origin 错配、租户越权、撤销/过期、多个凭据与
最后方法保护、跨连接额度竞争、审计故障回滚。旧平台 Bearer 自动化保持可用；
回退旧二进制不读取新平台文件，保留文件供重新升级使用。无需修改已发布迁移。

上游依据：[go-webauthn](https://pkg.go.dev/github.com/go-webauthn/webauthn/webauthn)、
[WebAuthn user verification](https://www.w3.org/TR/webauthn-3/#sctn-user-verification)。
