# 主域名租户控制台与网络冲突保护

## 问题与优先级

部署的公开开户使用绑定旧公网 IP 的租户域名；正式证书仅覆盖入口主机。
入口站的密码登录只查询入口租户，不能登录另外创建的独立网络。
先修复浏览器入口与登录，不合并用户数据库、不重置已有账户。

其次提供一个网络中的多个 IPv4 地址池，以及本地网络冲突检查。
这不是二层 VLAN；地址池本身不产生权限隔离，访问权限仍由 ACL/Grants 编译器决定。

## 浏览器入口

- 可选的 `self_service.console_url` 指向入口站的规范 HTTPS URL。
- 独立租户网页使用该地址下的 `/t/<organization>/`；组织 ID 只是路由选择，不是授权凭据。
- 路由仅允许租户网页 API、公开身份回调和控制台页面；禁止代理协议、平台后台和中继准入。
- 使用本租户独立持久会话，Cookie 为 host-only，Path 限定到该租户；不扩宽到父域。
- 注册响应增加独立 `console_url`；已有客户端 `organization.url` 保持控制面 URL。
- 入口登录明确选择网络标识，客户端不进行跨租户用户名/邮箱搜索。
- 浏览器 API、页面导航与运行时 OAuth/OIDC 回调统一使用控制台地址。
- 托管租户在共享 origin 上新启用的 passkey 使用租户专属 user-handle namespace，
  不更改已有独立 origin 的凭据语义，也不与平台管理员/入口 owner 的 handle 混用。
- 原主机路由继续存在，管理注册表及所有用户、设备、Noise 密钥无需重新建立。
- 独立官方客户端入口仍需运营者提供可解析的租户域名及受信证书；
  共享网页路径不冒充 TS2021 支持带路径的 login-server。

## 多地址池及安全边界

- 保留默认 IPv4 分配池语义和旧设备 IP；新增池与设备改 IP 共用合法性校验、
  跨租户冲突预留、版本检查、审计和套餐 entitlement。
- 删除/修改池不能悄悄回收仍使用中的地址；默认不自动移动设备。
- 多池是三层地址管理；跨池隔离通过现有可视化 ACL/Grants 明确配置，不能暗中更改协议。

## DNS 与本地网络冲突

上游 `net/tsaddr`、`net/dns` 与 `ipn/ipnlocal` 将 Quad100
（`100.100.100.100`、`fd7a:115c:a1e0::53`）定义为客户端内部服务地址。
控制面下发的 `DNSConfig` 没有设置这个虚拟监听地址的字段；仅设置
`--accept-dns=false` 不保证取消 Quad100 路由。

- 不伪造 DNS wire 字段，不宣称服务端能发现客户端未上报的所有本地网段。
- 分离地址池、子网路由、DNS 解析器这三类冲突；配置及接入入口提供可执行诊断。
- 客户端接入前若检测到必须保留的本地网络冲突，停止接管而不是继续执行并导致黑洞。
- 真正自动改写 Quad100 需客户端支持；官方客户端兼容路径采用明确保护/退出或
  经确认的 userspace 模式，不静默改变本机网络配置。

## 验证与回滚

注册、退出后再次密码登录、同名不同租户隔离、Cookie Path、未知网络、错误主机、
跨租户请求、身份回调及多凭据 namespace 必须有回归测试。
多地址池需要默认池兼容、冲突/版本/配额、旧地址保留、并发及 Map/DNS 地址投影测试。
Go 全量 build/vet/test/race，前端类型/单元/构建与真实浏览器链路。
涉及数据库升级时只追加迁移；生产上线先停止旧实例并完整备份，不覆盖用户数据。
