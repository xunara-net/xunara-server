# 路由与出口管理

## 使用与真实状态

「路由与出口」直接搜索、按子网/出口和状态筛选、分页并打开审批弹窗；设备
详情复用同一弹窗。勾选增删只形成草稿，先预览、再确认。成员只读，owner/admin
才能按 Entitlement 新增批准，降级仍可取消旧批准。出口和子网能力独立，
IPv4/IPv6 默认路由各占一条额度，不按套餐名称分支。

出口在审批弹窗中是一项「批准作为出口节点（IPv4 + IPv6）」，明确预览两条
默认路由的新增/取消并一次提交。官方客户端通过 `ContainsExitRoutes` 检查
`AllowedIPs` 同时包含 `0.0.0.0/0` 和 `::/0`，不取决于出口是否拥有公网 IPv6。
只批准其中一条时，保留实际批准记录并提示补全或取消，不标为官方可选出口。
停止任一默认路由的宣告也会撤下可选状态，保留批准不等于仍在提供出口。
底层审批 API 仍逐条处理显式差量，不偷偷补齐另一地址族，也不扩大已有 ACL。

区分待批准、已停止宣告、密钥过期、离线及「宣告与批准匹配」。匹配只描述
配置条件，不证明真实可达、正在转发或主路由选举成功；审批不修改 ACL、
防火墙、IP 转发或其它客户端偏好。出口列表保留最后一次自报选择与失效目标，
自报客户端数不等于活跃流量；读取失败不冒充空列表。

出口选择/停止命令只改变执行命令的本机，不含 Auth Key、登录重置或平台令牌。
手机在 APP 选择。离线、过期或状态未知只提供带警告的排查说明，不建议立即切换。

## 新管理 API

均为 Host 实际选中的租户，同源 Human Session 或 read/write API Scope。

| 路径 | 操作 |
|---|---|
| `/api/v2/routes/configuration` | GET 有界设备白名单、版本、CSRF、管理能力与实际额度 |
| `/api/v2/machines/{ref}/routes` | GET 单设备；POST revision 与 approve/unapprove 差量 |
| `/api/v2/exit-nodes` | GET 已批准出口与自报选择，既有 JSON 结构不变 |

定义/测试为 `control/route_management.go`、`networkconfig/routes.go`、
`state/route_approval.go` 及相应测试。ref 支持租户内数字 ID 或 stable ID。
版本绑定稳定身份、MachineKey/NodeKey、归属、宣告和批准，只输出不可逆摘要；
普通在线时间、名称或无关 NetInfo 不制造假冲突，不返回原始报告/密钥。

POST 要求当前 64 字符小写十六进制 revision；新增批准必须仍宣告，同一项不能
同时增删。每设备宣告/批准各限 256，单次差量限 256，总览合计限 2048；
超限 413 不截断，事务提交前校验响应上限。出口总览限 2048 节点/4096 条选择。
超大旧配置由管理员分批整理，不改客户端协议配额。缺设备 404、旧版本/宣告
变化 409、数据库故障 503；读写 no-store。

写入同 SQLite 事务取得写锁、复查持久角色/会话/服务 key，提交路由差量、
必需审计及配置通知版本。节点、审计或计数更新被拒绝/忽略均回滚；无差量
不新建审计/版本。提交后才通知 watchers。Cookie 要求 CSRF；服务 key 受 API
Entitlement 与 write Scope 约束，不通过菜单状态代替后端校验。

## 兼容与并发

旧 v1 API 与 HTML 表单委托同一流程，保留响应、差量顺序和预批准语义；不再
先读后覆盖或忽略审计失败。旧 Cookie v1 调用必须带 CSRF Header，服务写入
必须符合现有 API Entitlement；新 Web 不再混用旧审批入口。

MapRequest 遥测在事务内保留当前批准、标签、归属、有效期等管理事实，并核对
MachineKey/NodeKey/稳定身份；旧报告不能恢复批准或替换后的密钥。流断开只更新
last_seen，时间不倒退，不用整行旧节点快照覆盖审批或 Hostinfo。
Web 冲突/结果未知保留草稿，不自动重试；读取最新状态只重放明确增删意图，
保留其它管理员的新增批准，再要求用户重新预览确认。

审批不新增迁移，不改 TS2021/Noise/Map/DNS/DERP wire。子网路由仍按最低节点 ID
选举主路由；出口的 `0.0.0.0/0`、`::/0` 不参加此选举，每个已宣告且批准的出口
都保留在自身的 `AllowedIPs` 中，且不进入 `PrimaryRoutes`。出口由客户端显式选择，
不能让旧的离线出口屏蔽较新的已批准出口，也不因有另一个出口而自动切换客户端。

2026-10-20 现网排查复现了审批 API 显示新出口已批准、实际 netmap 却只给旧出口
默认路由的不一致。修复仅排除默认路由参加子网选举，保留子网主备、批准/撤销、
ACL 与租户边界。单出口测试不能覆盖此故障，回归必须包含两个出口并存，以及
新增/撤销批准后的真实 Noise 长轮询更新。此修复不等于所有手机网络已通过验收；
全 OS 出口现场验收、实时数据面与自动故障转移未交付。

## 2026-10-20 现网出口验收

服务端代码 `9fa46ca` 已替换现网二进制，保留旧二进制、配置及 10 个 SQLite 在线备份。
不更改原设备、路由审批、DNS 配置、ACL、套餐或其它客户端的出口偏好，也不发布新 APK。

| 检查 | 实际结果 |
|---|---|
| 审批 API 与官方客户端实际 netmap | 修复前两个出口已批准，但较新出口没有默认路由；修复后两个出口均保留默认路由 |
| 同租户官方 `tsnet` 对照 | IPv4/IPv6 双向 ICMP、TCP 通过；关闭探针 UDP 并指定部署默认 DERP 后仍通过 |
| 默认中继 | 完成注册准入、WireGuard 双向业务，不仅验证 TLS 握手；公网 UDP STUN 事务也通过 |
| 官方探针经在线 Android 官方客户端出口 | 双栈 peer API DNS 返回有效答案；IPv4 HTTPS 200 且验证证书链 |
| Xunara 0.5.2 模拟器经同一现网出口 | shell UID 真实 VPN 流量通过预解析 IPv4 HTTPS、VPN DNS 后 HTTPS、DNS UDP/TCP |
| IPv6 公网 | 隧道内 IPv6 和 DNS 可通，但公网 IPv6 TCP 收到复位，仍未通过验收 |

对照使用 Tailscale `v1.104.1` 的 `tsnet`、实际出口手机的官方 `1.98.8` 客户端，
以及 Rust 内核固定为 `ae6086e` 的 Xunara Android 0.5.2。模拟器探针明确加载 Android
系统 CA，不跳过证书校验，不用 App 自身被 VPN 排除的连接冒充出口成功。
纯 IP HTTP 目标返回 301，不能把非 200 的业务断言误判成 TCP 完全不通。

这不代表原 Xunara App 充当出口的手机已恢复：排查期间其旧设备离线，在线出口
使用的是官方客户端。用户手机间的实际重测和 IPv6 公网转发仍须单独确认，
不能用模拟器成功、控制面在线或单个 ICMP 回包替代。协议版本已核对：
按 [官方 v1.98.8 类型定义](https://github.com/tailscale/tailscale/blob/v1.98.8/tailcfg/tailcfg.go)，
`HomeDERP` 从 capability 111 起支持，现网官方客户端为 138，不能凭猜测改回旧字段。

诊断只创建独立短期机器凭据和临时节点，结束后撤销/删除；模拟器恢复原安装包、
原账号配置及网络开关，私钥和含业务流量的抓包不上传 Git。

## 验证

### 2026-10-20 双栈审批排查

在用户再次反馈「官方客户端显示出口未授权」后，重新读取线上数据库、审批 API
及真实官方客户端收到的 netmap，而非复用早先探针结论。本次快照显示：原官方
NX769J 保留双栈批准，但已经停止宣告默认路由；小米宣告双栈，却仅有 IPv4 批准。
此前总览按任意一条默认路由判定出口，错误地将后一种状态标成可用，且将前一种
自报选择标为有效。它们不是新的中继故障，也不能通过重启中继恢复授权。

修正管理状态与 Web 判定以符合官方双栈要求；保留部分批准和失效选择供排查，
不自动更改原手机的批准或本地设置。审批弹窗不再拆开两种地址族供普通操作。
现网独立短期官方探针已验证自身的批准推送：未批准/只批准 IPv4 不可选，显式
补齐 IPv6 后立即可选，撤销后恢复不可选。回归同时检查出口提供端自己的 `Node`
以及消费者的 `Peers`，不只看 Web 列表，也不伪造另一台手机的私钥。

此验收只确认授权生命周期，不代表原手机间的出口数据面或 IPv6 公网已恢复；
还须确认用户当前提供出口的是哪台手机，并重新做实际出网测试。

执行目录：`xunara-server` 根目录，Go 版本按 `go.mod`。

```sh
go build ./...
go vet ./...
go test ./... -count=1
go test -race ./... -count=1 -timeout=30m
```

包含审计 ABORT/IGNORE、计数更新忽略、两连接 CAS/旧差量合并、撤销/降权、
跨租户/Scope、新旧入口一致、套餐独立门禁/降级清理、有界读写及真实 DB 故障。
官方 Noise 验证批准/撤销 AllowedIPs/PrimaryRoutes 与旧遥测；Web 验证真实 API、
手机审批、失败/冲突草稿及只读成员。线上不创建测试人类账号或替换正式凭据。

前一轮 `9fa46ca` 的服务端 build/vet/test、Staticcheck、完整 race 及官方客户端分享 race 集成均通过，
中继 build/vet/test/race 也通过。首次完整 race 沿用默认 10 分钟预算而超时，未记为通过；
按仓库 CI 既有的 `-timeout=30m` 重跑后通过，control 包耗时 1146.180 秒。
未因超时缩减真实密码哈希、数据库事务或协议回归，也未将公网 IPv6 失败记为成功。
